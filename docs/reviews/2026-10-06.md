### ① — (carried, still OPEN) Attack timing model: `speed + flat ticks` (docs, PC-DEC-034/055) vs `speed × multiplier` (code, PC-107..110b)

Re-verified still live in code this pass: `js/combat/engine.js` monster windup and
cooldown still use `Math.max(1, Math.floor(mon.speed * rollMultiplier(...)))`
(L182-185, L318), with the comment at L179 citing "PC-107: windup = mon.speed *
prepare multiplier (not speed + flat ticks)". The docs still describe the old
formula:

| | Side A (decided rule — PC-DEC-034/055, Spahrep) | Side B (code — PC-107..110b) |
|---|---|---|
| Monster windup | `mon.speed + rollStat(prepare_time, prepare_time_range)` (battle-status-ui.md:237) | `max(1, floor(mon.speed * rollMultiplier(prepare_time_multiplier, ...)))` (engine.js L182-183) |
| Monster cooldown | `mon.speed + rollStat(cooldown_time, cooldown_time_range)` (battle-status-ui.md:239) | `max(1, floor(mon.speed * rollMultiplier(cooldown_time_multiplier, ...)))` (engine.js L185, L318) |

Stale docs (still describe Side A):
- **battle-status-ui.md** L237, L239 (`mon.speed + rollStat(...)`)
- **current-design-status.md** L68 (monster rows describe flat-tic stepping; L72
  the PC-DEC-055 opening seed is cooldown at `mon.speed`, unaffected)

  `speed + flat ticks` rule verbatim)

### ② — (carried, minor) Initial Action Queue creation row reads as a `winding` row

`70acae4` renders the initial Action Queue creation as `<Monster> getting ready`
before it flips to `<Monster> recovering`. Per PC-DEC-060 the opening row is a
**cooldown** row at `mon.speed` — "getting ready" is windup language. The code

drift, not an engine contradiction, and the label may be intentional user-facing
flavor. Low priority; recommend confirming the label or docs-note it.
