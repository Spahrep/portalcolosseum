### ① — (carried, still OPEN) Attack timing model: `speed + flat ticks` (docs, PC-DEC-034/055) vs `speed × multiplier` (code, PC-107..110b)

prepare/cooldown ticks`; the shipped engine computes timing as a pure multiplier
on speed and has dropped the flat timing columns. Re-verified still live in code
this pass: `js/combat/engine.js` `queueNextMonsterAttack` and the monster cooldown
insert use `Math.max(1, Math.floor(mon.speed * rollMultiplier(prepare_time_multiplier, ...)))`
and `Math.max(1, Math.floor(mon.speed * rollMultiplier(cooldown_time_multiplier, ...)))`.

| | Side A (decided rule — PC-DEC-034/055, Spahrep) | Side B (code — PC-107..110b) |

| Monster cooldown | `mon.speed + rollStat(cooldown_time, cooldown_time_range)` (battle-status-ui.md:239) | `max(1, floor(mon.speed * rollMultiplier(cooldown_time_multiplier, ...)))` (engine.js) |
