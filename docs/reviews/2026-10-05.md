### ① — (carried, still OPEN) Attack timing model: `speed + flat ticks` (docs, PC-DEC-034/055) vs `speed × multiplier` (code, PC-107..110b)

Re-verified still live in code this pass: `js/combat/engine.js`
`queueNextMonsterAttack` and the monster cooldown insert use
`Math.max(1, Math.floor(mon.speed * rollMultiplier(prepare_time_multiplier, ...)))`
and `Math.max(1, Math.floor(mon.speed * rollMultiplier(cooldown_time_multiplier, ...)))`
(L182-185, L318; the comment at L179 explicitly cites "PC-107: windup = mon.speed
* prepare multiplier (not speed + flat ticks)"). PC-107/108/109/110 shipped on
main — the decided flat ticks are dropped and the code comment names that
reversal. Note also engine.js L671 uses plain `mon.speed` as the cooldown tics
on a separate path, a third variant — worth folding into any reconciliation.

| | Side A (decided rule — PC-DEC-034/055, Spahrep) | Side B (code — PC-107..110b) |
|---|---|---|
| Monster windup | `mon.speed + rollStat(prepare_time, prepare_time_range)` (battle-status-ui.md:237) | `max(1, floor(mon.speed * rollMultiplier(prepare_time_multiplier, ...)))` (engine.js L182-183) |
| Monster cooldown | `mon.speed + rollStat(cooldown_time, cooldown_time_range)` (battle-status-ui.md:239) | `max(1, floor(mon.speed * rollMultiplier(cooldown_time_multiplier, ...)))` (engine.js L185, L318) |
